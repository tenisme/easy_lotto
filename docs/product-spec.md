## 1. 제품 개요

Easy Lotto는 로또 6/45 번호를 다양한 조건으로 생성하고, 마음에 드는 숫자와 조합을 저장하여 실제 복권 구매 시 쉽게 따라 표시할 수 있게 돕는 개인용 유틸리티 앱이다.

앱은 당첨을 예측하거나 당첨 확률을 높여준다고 주장하지 않는다. 모든 추천 옵션은 사용자의 번호 선택 취향을 반영하거나 조합을 정리하기 위한 도구다.

### 1.1 해결하려는 문제

- 기존 번호 추천 앱은 옵션 이름만 보여줘 초보자가 의미를 이해하기 어렵다.
- 숙련 사용자는 원하는 필터가 없으면 앱의 효용을 느끼기 어렵다.
- 추천받은 숫자, 완성된 6개 조합, 실제 구매용 조합을 한곳에서 관리하기 어렵다.
- 복권 판매점에서 저장한 조합을 보며 종이 용지에 옮겨 표시하기 불편하다.

### 1.2 핵심 가치

- **친절함:** 모든 옵션에 쉬운 설명과 제약 조건을 제공한다.
- **선택권:** 초보자는 기본 설정으로, 숙련자는 세부 조건으로 번호를 생성한다.
- **연결성:** 추천, 저장, 복권 용지 구성, 번호 크게 보기가 하나의 흐름으로 이어진다.
- **정직함:** 통계와 취향 기반 선택을 확률 예측처럼 포장하지 않는다.

## 2. 대상 사용자

대한민국에서 로또 6/45를 구매할 수 있는 성인 중 다음 사용자를 대상으로 한다.

### 초보 사용자

- 옵션 용어에 익숙하지 않다.
- 복잡한 설정 없이 번호를 빠르게 추천받고 싶다.
- 각 옵션이 결과에 어떤 영향을 주는지 쉬운 설명을 원한다.

### 숙련 사용자

- 고정수, 제외수, 홀짝 비율 등 자신만의 선택 기준이 있다.
- 마지막 설정을 반복해서 사용하고 싶다.
- 과거 당첨 결과의 분포를 참고 자료로 확인하고 싶다.

## 3. 제품 원칙과 제한

1. 1부터 45까지 서로 다른 숫자 6개를 한 게임으로 취급한다.
2. 유효한 모든 6개 조합의 1등 당첨 확률은 동일하다.
3. 과거 결과는 미래 추첨 결과를 예측하지 못한다.
4. `직전 회차 번호 제외`, `미출현 번호 포함` 등의 기능에는 확률상 유리하다는 표현을 사용하지 않는다. 확률 안내는 각 옵션마다 반복하지 않고 최초 안내와 `더보기 → 번호 추천 방식 안내`에서 한 번에 제공한다.
5. 생성 조건이 충돌하면 반복 시도 후 실패시키지 않고, 가능하면 생성 전에 원인과 해결 방법을 알려준다.
6. 사용자의 번호와 복권 용지는 초기 버전에서 기기 내부에만 저장한다.
7. 실제 복권 구매, 자동 구매, 당첨 보장 또는 투자 조언 기능은 제공하지 않는다.

### 3.1 사용자 문구 말투

- 설명, 안내, 완료 메시지와 오류 문구는 기본적으로 `~습니다`, `~할 수 있습니다` 형식을 사용한다.
- 확인 질문은 `~하시겠습니까?` 형식을 사용한다.
- 버튼은 `저장`, `번호 크게 보기`, `설정 수정`처럼 짧고 대상을 알 수 있는 동작명으로 표시한다.
- 친근한 말투를 위해 `~아요`, `~어요`를 혼용하지 않는다.

## 4. 핵심 사용자 흐름

### 4.1 번호 추천 및 저장

1. 사용자가 생성할 게임 수를 1~5개 중 선택한다.
2. `완전 랜덤` 또는 `상세 설정`을 선택한다. 선택만으로 화면이 바뀌지는 않는다.
3. 완전 랜덤에서는 `번호 생성`을 누른다. 상세 설정을 저장한 적이 없으면 `설정 만들기`로 상세 설정 화면을 연다. 저장된 상세 설정이 있으면 홈에서 사용할 설정을 선택한 뒤 `설정 수정`으로 편집하거나 `번호 생성`으로 바로 생성한다.
4. 앱이 생성 요청의 유효성을 검사하고, 선택한 방식과 설정을 충족하는 번호 조합을 생성하여 추천 결과 화면을 연다.
5. 사용자는 결과에서 개별 숫자를 `내 번호`로 토글하거나 6개 조합 전체를 저장한다.

### 4.2 나만의 복권 용지 만들기

1. 사용자가 저장된 번호 조합을 선택하거나 새 조합을 만든다.
2. 새 조합은 `직접 선택`, `내 번호`, `완전 랜덤`, `상세 설정` 중 하나로 만든다. 새 조합을 `저장한 조합`에 저장하지 않아도 복권 용지에 바로 추가할 수 있다.
3. 최대 5개 조합을 용지에 추가한다.
4. 제목을 지정하고 하나의 복권 용지로 저장한다.
5. 저장된 용지를 번호 크게 보기 화면으로 연다.

### 4.3 실제 구매 시 사용

1. 사용자가 저장된 복권 용지를 선택한다.
2. `번호 크게 보기`를 선택하면 앱은 한 화면에 최대 5개 게임을 크고 명확하게 표시한다.
3. 사용자가 종이 복권 용지에 번호를 옮겨 표시한다.
4. 해당 화면이 열려 있는 동안 화면 자동 꺼짐 방지를 선택적으로 적용한다.

## 5. 화면 구조

초기 정보 구조는 하단 탭 3개와 보조 화면으로 구성한다.

### 5.1 추천

- 생성할 게임 수 선택: 1~5
- `완전 랜덤`과 `상세 설정` 선택 카드: 테두리 또는 배경으로 선택 상태 표시
- 현재 적용된 옵션 요약
- 생성 방식과 저장된 상세 설정 유무에 따른 버튼: 아래 표 참고
- 생성 결과 카드
- 개별 숫자 `내 번호` 저장 토글
- 결과 카드에서 각 번호 아래의 하트를 해당 번호의 가로 중심에 맞춰 배치한다. `조합 저장` 버튼은 이 정렬을 밀어내지 않도록 별도 영역에 둔다.
- 조합 전체 저장 토글
- 설정 초기화

#### 5.1.1 추천 홈 버튼과 이동 규칙

| 홈에서 선택한 방식 | 저장된 상세 설정 | 표시할 버튼 | 버튼 동작 |
|---|---|---|---|
| 완전 랜덤 | 유무와 무관 | `번호 생성` 1개 | 상세 조건 없이 선택한 게임 수만큼 생성한 뒤 추천 결과 화면으로 이동한다. |
| 상세 설정 | 없음 | `설정 만들기` 1개 | 상세 설정 화면으로 이동한다. 이 버튼 자체로 번호를 생성하지 않는다. |
| 상세 설정 | 있음, 선택 전 | 왼쪽 `설정 수정`, 오른쪽 `번호 생성` 모두 비활성 | 선택 필드의 `설정 선택`을 눌러 사용할 설정을 먼저 선택하게 한다. |
| 상세 설정 | 있음, 선택 완료 | 왼쪽 `설정 수정`, 오른쪽 `번호 생성` | `설정 수정`은 선택한 설정의 편집 화면으로 이동한다. `번호 생성`은 선택한 설정으로 번호를 생성한 뒤 추천 결과 화면으로 바로 이동한다. |

완전 랜덤으로 전환해도 저장된 상세 설정을 삭제하거나 덮어쓰지 않는다. 상세 설정 카드 선택과 상세 설정 편집 진입을 구분하며, 편집 화면은 `설정 만들기` 또는 `설정 수정` 버튼으로 연다. 상세 화면의 모든 옵션이 기본값인 것과 사용자가 상세 설정을 한 번 저장한 것은 서로 다른 상태다.

상세 설정 카드 아래에는 저장된 설정을 고르는 선택 필드를 표시한다. 저장된 설정이 없으면 `저장한 설정이 없습니다`를 표시하고 필드를 비활성화한다. 저장된 설정이 있으나 현재 선택값이 없으면 `설정 선택`을 표시한다. 필드를 누르면 바텀 시트에서 저장한 설정을 라디오 목록으로 보여주며 하나만 선택할 수 있다. 선택 후에는 필드에 설정 이름을 표시하고, `설정 수정`과 `번호 생성`을 활성화한다. 마지막으로 선택한 유효한 설정은 다시 앱을 열었을 때 복원한다.

와이어프레임의 상태별 명세와 남은 검토 사항은 `docs/wireframes.md`를 따른다.

보관함, 저장 설정 관리, 복권 용지와 번호 크게 보기 화면의 초안은 `docs/storage-wireframes.md`를 따른다.

화면 상태, 저장 구조와 추천 엔진의 구현 계약 초안은 `docs/implementation-design.md`를 따른다.

### 5.2 보관함

- `나만의 복권 용지`: 최대 5개 조합으로 만든 용지

- 개인정보처리방침과 오픈소스 라이선스
- 후원 기능(정책 검토 후 도입하는 경우)

### 5.4 보조 화면

## 6. 기능 요구사항

### 6.1 번호 생성

| ID | 요구사항 | 우선순위 |
|---|---|---|
| GEN-01 | 조건 없이 1~45에서 서로 다른 숫자 6개를 무작위 생성한다. | 필수 |
| GEN-02 | 한 번에 1~5개의 서로 다른 게임을 생성한다. | 필수 |
| GEN-03 | 모든 결과는 오름차순으로 표시한다. | 필수 |
| GEN-04 | 고정수 0~6개와 제외수를 지정할 수 있다. 제외 후에는 조합을 완성할 후보가 충분히 남아야 한다. | 필수 |
| GEN-05 | 홀수 개수와 낮은 수 개수를 각각 `제한 없음` 또는 0~6개로 지정할 수 있다. | 필수 |
| GEN-06 | 총합을 `제한 없음`, 사전 정의 구간 또는 직접 범위로 지정할 수 있다. | 필수 |
| GEN-07 | 연속수를 `제외`, `1묶음`, `2묶음`, `3묶음`, `제한 없음` 중 하나로 지정하고, 1묶음과 2묶음에서는 묶음 길이를 추가로 지정할 수 있다. | 필수 |
| GEN-08 | 직전 회차 번호를 `허용`하거나 `제외`할 수 있으며, 제외 범위를 본번호 6개 또는 보너스 포함 7개로 선택할 수 있다. | 필수 |
| GEN-09 | 최근 N회 동안의 미출현 번호를 계산할 때 본번호 6개 또는 보너스 포함 7개를 출현 기준으로 선택하고, 미출현 번호를 정확히 K개 포함할 수 있다. | 필수 |
| GEN-10 | 조건 충돌을 생성 전에 검사하고 구체적인 오류를 표시한다. | 필수 |
| GEN-11 | 같은 생성 요청에서 중복 조합을 반환하지 않는다. | 필수 |
| GEN-12 | 사용자가 저장한 상세 설정을 기기에 보관하고 홈에서 다시 선택하여 사용한다. 완전 랜덤 선택이나 아직 저장하지 않은 편집 값이 저장된 상세 설정을 덮어쓰지 않는다. | 필수 |
| GEN-13 | 모든 옵션을 기본값으로 되돌릴 수 있다. | 필수 |
| GEN-14 | 상세 설정을 여러 개 저장하고 이름으로 구분할 수 있다. 최초 저장 시 이름을 입력받고, 빈 이름은 `설정1`, `설정2`처럼 사용되지 않은 가장 작은 번호로 자동 지정한다. 이름은 나중에 수정할 수 있다. | 필수 |

#### 6.1.1 확정된 옵션 동작과 범위

| 옵션 | 상태와 입력 범위 | 기본값 | 확정 동작 |
|---|---|---|---|
| 생성 게임 수 | 1~5게임 | 1게임 | 한 요청 안에서 동일한 6개 조합을 중복 생성하지 않는다. |
| 고정수 | 1~45에서 0~6개 | 선택 없음 | 선택한 모든 숫자를 각 추천 조합에 반드시 포함한다. `내 번호`에서 불러올 수 있다. |
| 제외수 | 1~45에서 0~39개 | 선택 없음 | 선택한 숫자를 후보에서 제거한다. 고정수와 같은 숫자를 선택할 수 없다. 실제 허용 개수는 다른 제외 규칙 적용 후 조합을 완성할 수 있어야 한다. |
| 홀짝 구성 | 제한 없음 또는 홀수 0~6개 | 제한 없음 | 결과의 홀수 개수가 지정값과 정확히 같아야 한다. 짝수 개수는 `6 - 홀수 개수`다. |
| 고저 구성 | 제한 없음 또는 낮은 수 0~6개 | 제한 없음 | `1~22`를 낮은 수, `23~45`를 높은 수로 정의한다. 낮은 수 개수가 지정값과 정확히 같아야 한다. |
| 총합 범위 | 제한 없음, 낮음 21~104, 중간 105~174, 높음 175~255, 직접 설정 21~255 | 제한 없음 | 6개 숫자의 합이 선택한 최소값 이상, 최대값 이하여야 한다. 직접 설정은 최소값이 최대값보다 클 수 없다. 구간 명칭은 확률적 유불리가 아닌 합계 분류다. |
| 연속 묶음 수 | 제외, 1묶음, 2묶음, 3묶음, 제한 없음 | 제한 없음 | 차이가 1인 숫자가 2개 이상 이어진 최대 구간을 한 묶음으로 계산한다. 화면에는 `제외 → 1묶음 → 2묶음 → 3묶음 → 제한 없음` 순서로 표시한다. |
| 1묶음 연속 숫자 수 | 제한 없음 또는 정확히 2~6개 | 제한 없음 | `1묶음`을 선택했을 때만 표시한다. 정확한 길이를 선택하면 해당 길이의 연속 묶음이 하나만 있어야 한다. |
| 2묶음 구성 | 제한 없음, 2+2, 2+3, 2+4, 3+3 | 제한 없음 | `2묶음`을 선택했을 때만 표시한다. 두 묶음의 표시 순서는 구분하지 않으므로 3+2는 2+3과 같다. |
| 직전 회차 번호 | 허용 또는 제외 | 허용 | `허용`은 직전 번호를 일반 후보로 둔다. `제외`는 선택한 범위의 직전 번호를 후보에서 제거한다. 직전 번호를 강제로 포함하는 기능은 아니다. |
| 직전 회차 제외 범위 | 본번호 6개, 보너스 포함 7개 | 보너스 포함 7개 | 직전 회차 번호가 `제외`일 때만 표시하고 적용한다. |
| 미출현 기준 기간 N | 최근 5회, 10회, 20회 또는 직접 설정 1~100회 | 최근 5회 | 선택한 회차 범위에 한 번도 출현하지 않은 숫자 집합을 계산한다. 검증된 데이터가 N회보다 적으면 사용할 수 없다. |
| 미출현 판정 범위 | 본번호 6개, 보너스 포함 7개 | 보너스 포함 7개 | 각 회차에서 어떤 번호를 `출현`으로 셀지 결정한다. 두 선택지의 사용 비율을 측정해 기본값 변경 여부를 검토한다. |
| 미출현 번호 포함 수 K | 사용 안 함 또는 정확히 1~6개 | 사용 안 함 | 계산된 미출현 숫자 중 정확히 K개가 결과에 포함되어야 한다. 어떤 미출현 숫자를 포함할지는 다른 활성 규칙을 모두 만족하는 후보 중에서 무작위로 정한다. |

외부 데이터가 필요한 옵션은 검증된 최신 로컬 데이터로 계산한다. 동기화 실패 시 마지막으로 검증된 데이터를 사용하고, 데이터가 없거나 필요한 회차 수보다 부족하면 해당 옵션만 비활성화한다.

출처 조사와 동기화·검증 설계는 `docs/draw-data-research.md`를 따른다. 사용자가 전달한 동행복권 회신에 따르면 역대·최신 당첨 기록 등은 `출처 : 동행 복권`을 명확히 표시하는 조건으로 상업적 이용이 가능하며, 조회 경로는 동행복권 웹페이지와 공개 API 중 선택할 수 있다. 주 1회 필요한 데이터만 조회하는 방식으로 설계한다. 실제 주소와 응답 형식은 연동 시 확인한다.

### 6.2 옵션 도움말

| ID | 요구사항 |
|---|---|
| HELP-01 | 모든 옵션명 옆에 도움말 버튼을 제공한다. |
| HELP-02 | 도움말은 정의, 결과에 미치는 영향, 입력 가능 범위를 설명한다. |
| HELP-03 | 확률과 과거 데이터의 한계는 최초 안내와 `더보기 → 번호 추천 방식 안내`에서 제공하고, 개별 옵션 도움말에는 동작 설명을 중심으로 제공한다. |
| HELP-04 | 긴 설명은 작은 툴팁에 억지로 넣지 않고 바텀 시트 또는 대화상자로 제공한다. |

도움말 문구 예시:

- **고정수:** 선택한 숫자를 모든 추천 조합에 포함하고 나머지 자리를 무작위로 채운다.
- **제외수:** 선택한 숫자를 추천 후보에서 제거한다.
- **홀짝 구성:** 한 조합에 포함할 홀수의 개수를 정한다.
- **고저 구성:** 1~22와 23~45에서 각각 몇 개를 포함할지 정한다.
- **총합 범위:** 6개 숫자의 합이 지정한 범위 안에 들도록 생성한다.
- **연속 묶음:** 차이가 1인 숫자가 2개 이상 이어진 구간이다. 서로 떨어진 연속 구간은 각각 다른 묶음으로 센다.
- **연속수 제외:** 연속 묶음이 없는 조합만 생성한다.
- **연속수 1묶음:** 연속 묶음이 정확히 하나인 조합을 생성한다. 묶음의 연속 숫자 수를 제한 없음 또는 2~6개로 지정할 수 있다.
- **연속수 2묶음:** 연속 묶음이 정확히 두 개인 조합을 생성한다. 묶음 구성을 제한 없음, 2+2, 2+3, 2+4, 3+3 중에서 지정할 수 있다.
- **연속수 3묶음:** 연속 묶음이 정확히 세 개인 조합을 생성한다. 6개 번호가 자동으로 2+2+2 구성되므로 길이 설정은 표시하지 않는다.
- **연속수 제한 없음:** 연속 묶음의 유무, 개수와 길이를 제한하지 않는다.
- **직전 회차 번호 허용:** 직전 회차 번호도 일반 번호와 동일하게 추천 후보로 사용한다. 다른 설정을 만족하면 결과에 포함될 수 있지만 반드시 포함되지는 않는다.
- **직전 회차 번호 제외:** 직전 회차에서 추첨된 번호를 추천 후보에서 제거한다. 다른 설정을 만족하는 숫자라도 선택한 제외 범위에 해당하면 결과에 포함되지 않는다.
- **직전 회차 제외 범위:** 본번호 6개만 제외하거나 보너스를 포함한 7개 모두를 제외한다.
- **미출현 번호:** 최근 N회 동안 한 번도 출현하지 않은 숫자 중 정확히 K개가 포함되도록 생성한다.
- **미출현 판정 범위:** 각 회차의 본번호 6개만 출현으로 보거나 보너스를 포함한 7개 모두를 출현으로 본다.

앱 전체 확률 안내 문구:

> Easy Lotto는 사용자가 선택한 조건에 따라 번호 조합을 만들어주는 도구입니다. 추첨은 매회 독립적으로 이루어지며, 과거 결과와 추천 조건은 당첨을 예측하거나 보장하지 않습니다. 다양한 번호 선택 방식을 편리하게 즐기는 용도로 이용할 수 있습니다.

### 6.3 옵션 검증 및 충돌 조건

검증은 `입력 자체 검증 → 데이터 상태 검증 → 명시적 규칙 충돌 검증 → 전체 조합 가능성 검증 → 요청한 고유 게임 수 검증` 순서로 수행한다. 하나의 설정에서 여러 문제가 발견되면 수정에 도움이 되도록 관련 오류를 함께 보여준다.

#### 6.3.1 단일 옵션 검증

| 대상 | 충돌 또는 잘못된 상태 | 처리 및 안내 |
|---|---|---|
| 모든 숫자 입력 | 1~45 범위 밖의 값 또는 같은 목록 안의 중복 | 저장·생성을 막고 잘못된 숫자를 표시한다. |
| 생성 게임 수 | 1~5 범위 밖 | 저장·생성을 막고 허용 범위를 안내한다. |
| 고정수 | 7개 이상 | “고정수는 최대 6개까지 선택할 수 있습니다.” |
| 제외수 | 모든 제외 규칙 적용 후 조합을 완성할 후보가 부족함 | 부족한 후보 수와 완화할 제외 옵션을 안내한다. |
| 홀짝 구성 | 제한 없음이 아닌데 0~6 범위 밖 | 저장·생성을 막는다. |
| 고저 구성 | 제한 없음이 아닌데 0~6 범위 밖 | 저장·생성을 막는다. |
| 총합 직접 설정 | 범위 밖, 최소값 > 최대값 | 가능한 전체 범위 21~255와 입력 오류를 안내한다. |
| 직전 회차 제외 | 검증된 직전 회차 데이터가 없음 | 마지막 검증 회차를 표시하고 옵션을 비활성화한다. |
| 미출현 기준 기간 | 1~100 범위 밖 또는 검증 데이터가 N회보다 적음 | 사용할 수 있는 최대 회차 수를 안내하고 옵션을 비활성화한다. |
| 미출현 포함 수 | 사용 안 함이 아닌데 1~6 범위 밖 | 저장·생성을 막는다. |
| 미출현 숫자 집합 | 계산된 미출현 숫자가 K개보다 적음 | 현재 기준으로 가능한 최대 K를 알려주고 값을 낮추게 한다. |
| 1묶음 연속 숫자 수 | 제한 없음이 아닌데 2~6 범위 밖 | 저장·생성을 막고 허용 범위를 안내한다. |
| 2묶음 구성 | 허용된 구성 외의 값 | 저장·생성을 막고 2+2, 2+3, 2+4, 3+3 중에서 선택하게 한다. |

#### 6.3.2 옵션 간 충돌 표

| 함께 적용한 옵션 | 충돌 조건 | 처리 및 사용자 안내 |
|---|---|---|
| 고정수 × 제외수 | 같은 숫자가 양쪽에 존재 | 어느 숫자가 겹치는지 표시하고 둘 중 한쪽에서 해제하도록 한다. |
| 고정수 × 직전 회차 제외 | 고정수가 선택한 직전 회차 제외 범위에 포함 | “고정수 N은 직전 회차 번호 제외 설정과 충돌합니다.” |
| 고정수 × 홀짝 구성 | 고정 홀수 개수가 목표 홀수 개수보다 많거나, 남은 자리로 목표에 도달할 수 없음 | 현재 고정수의 홀짝 구성과 가능한 목표 범위를 표시한다. |
| 고정수 × 고저 구성 | 고정된 낮은 수 개수가 목표보다 많거나, 남은 자리로 목표에 도달할 수 없음 | 현재 고정수의 고저 구성과 가능한 목표 범위를 표시한다. |
| 고정수 × 총합 범위 | 고정수 합과 남은 후보의 최소·최대 합을 고려해도 선택 범위에 도달할 수 없음 | 가능한 총합 범위를 계산해 보여준다. |
| 고정수 × 연속수 제외 | 고정수 자체에 연속된 숫자가 있음 | 충돌하는 연속 숫자를 표시한다. |
| 고정수 × 연속 묶음 수·구성 | 고정수로 이미 허용 묶음 수나 길이를 초과했거나, 남은 자리로 지정 구성을 완성할 수 없음 | 현재 고정수가 만든 묶음과 완성 가능한 구성을 표시한다. |
| 고정수 × 미출현 K개 | 고정수에 포함된 미출현 숫자가 K개보다 많거나, 고정수와 남은 후보를 합쳐도 K개를 채울 수 없음 | 현재 포함된 미출현 숫자 수와 가능한 K 범위를 표시한다. |
| 제외수 × 홀짝 구성 | 제외 후 남은 홀수 또는 짝수 후보로 목표 개수를 채울 수 없음 | 부족한 분류와 필요한 후보 수를 안내한다. |
| 제외수 × 고저 구성 | 제외 후 남은 낮은 수 또는 높은 수 후보로 목표 개수를 채울 수 없음 | 부족한 분류와 필요한 후보 수를 안내한다. |
| 제외수 × 총합 범위 | 남은 후보 6개로 만들 수 있는 최소·최대 합과 선택 범위가 겹치지 않음 | 가능한 총합 범위를 표시한다. |
| 제외수 × 연속 묶음 수·구성 | 남은 후보와 고정수로 지정한 묶음 수와 길이 구성을 만들 수 없음 | 연속수 조건 또는 제외수를 완화하도록 한다. |
| 제외수 × 미출현 K개 | 제외되지 않은 미출현 후보가 고정수를 고려해도 K개보다 적음 | 가능한 최대 K를 표시한다. |
| 직전 회차 제외 × 홀짝 구성 | 직전 번호 제거 후 홀수·짝수 후보가 목표에 부족함 | 직전 번호 처리 또는 홀짝 구성을 변경하도록 한다. |
| 직전 회차 제외 × 고저 구성 | 직전 번호 제거 후 낮은 수·높은 수 후보가 목표에 부족함 | 직전 번호 처리 또는 고저 구성을 변경하도록 한다. |
| 직전 회차 제외 × 총합 범위 | 직전 번호 제거 후 가능한 총합 범위와 선택 범위가 겹치지 않음 | 계산된 가능 범위를 표시한다. |
| 직전 회차 제외 × 연속 묶음 수·구성 | 직전 번호 제거 후 지정한 묶음 수와 길이 구성을 만들 수 없음 | 직전 번호 처리 또는 연속수 조건을 변경하도록 한다. |
| 직전 회차 제외 × 미출현 K개 | 직전 제외 대상과 미출현 후보가 겹쳐 사용 가능한 미출현 숫자가 K개보다 적음 | 가능한 최대 K와 겹쳐 제거된 숫자를 표시한다. |
| 홀짝 구성 × 고저 구성 | 남은 후보의 네 분류(낮은 홀수·낮은 짝수·높은 홀수·높은 짝수)로 두 목표를 동시에 충족할 수 없음 | 각 목표는 따로 가능하더라도 함께 불가능함을 안내한다. |
| 홀짝 구성 × 총합 범위 | 해당 홀짝 구성으로 가능한 최소·최대 합과 총합 범위가 겹치지 않음 | 해당 홀짝 구성에서 가능한 총합 범위를 표시한다. |
| 홀짝 구성 × 연속수 | 지정한 홀짝 수와 연속수 조건을 함께 만족하는 후보 조합이 없음 | 두 조건 중 하나를 완화하도록 한다. |
| 홀짝 구성 × 미출현 K개 | 미출현 후보의 홀짝 구성과 나머지 후보로 목표 홀수 개수를 만들 수 없음 | 가능한 홀수 개수 또는 K 범위를 표시한다. |
| 고저 구성 × 총합 범위 | 해당 고저 구성으로 가능한 최소·최대 합과 총합 범위가 겹치지 않음 | 해당 고저 구성에서 가능한 총합 범위를 표시한다. |
| 고저 구성 × 연속수 | 지정한 고저 수와 연속수 조건을 함께 만족하는 후보 조합이 없음 | 두 조건 중 하나를 완화하도록 한다. |
| 고저 구성 × 미출현 K개 | 미출현 후보의 고저 구성과 나머지 후보로 목표 낮은 수 개수를 만들 수 없음 | 가능한 낮은 수 개수 또는 K 범위를 표시한다. |
| 총합 범위 × 연속수 | 선택한 합계 구간에서 연속수 조건을 만족하는 조합이 없음 | 가능한 총합 범위 또는 연속수 조건 변경을 안내한다. |
| 총합 범위 × 미출현 K개 | 미출현 K개를 포함했을 때 가능한 최소·최대 합과 총합 범위가 겹치지 않음 | 해당 K에서 가능한 총합 범위를 표시한다. |
| 연속수 × 미출현 K개 | 미출현 K개 조건과 연속수 조건을 함께 만족하는 조합이 없음 | 연속수 조건 또는 K를 완화하도록 한다. |
| 모든 활성 옵션 | 각 쌍은 가능하지만 전체를 동시에 만족하는 조합이 없음 | 충돌 가능성이 큰 옵션을 표시하고 한 번에 하나씩 완화하도록 제안한다. 임의로 옵션을 무시하지 않는다. |
| 모든 활성 옵션 × 생성 게임 수 | 유효 조합은 존재하지만 요청한 수만큼 서로 다른 조합이 없음 | 가능한 고유 게임 수를 표시하고 게임 수 또는 조건을 변경하도록 한다. |

`내 번호` 저장 상태는 추천 규칙이 아니므로 제외수나 직전 회차 제외와 충돌하지 않는다. 저장된 숫자는 그대로 유지하며, 고정수로 선택했을 때만 위 충돌 검사를 적용한다.

연속 묶음은 항상 더 이상 좌우로 확장할 수 없는 최대 연속 구간으로 판정한다. 예를 들어 `1, 2, 3`은 `1, 2`와 `2, 3` 두 쌍이 아니라 길이 3의 한 묶음이다. `1, 2, 8, 9`는 길이 2의 두 묶음이다. 정확한 묶음 길이를 지정한 경우 남는 단일 숫자가 기존 묶음을 늘리거나 새로운 묶음을 만들면 유효하지 않다.

상위 연속수 옵션을 바꾸면 적용되지 않는 하위 옵션은 화면에서 숨기고 생성 규칙에서도 무시한다. 같은 설정 세션에서 1묶음이나 2묶음으로 돌아오면 이전 하위 선택값을 복원하되, 전체 옵션 초기화 시에는 모두 `제한 없음`으로 되돌린다.

### 6.4.1 상세 설정 저장과 이름

| ID | 요구사항 |

| PRESET-05 | 이름의 앞뒤 공백을 제거하고 빈 문자열은 미입력으로 처리한다. 같은 이름은 구별하기 어려우므로 중복 저장하지 않는다. |

### 6.5.1 추천 결과 이탈과 미저장 결과

| ID | 요구사항 |
|---|---|
| RESULT-01 | 추천 결과 상단에 현재 적용한 설정 이름과 요약을 표시한다. 저장된 설정이면 동작 행 오른쪽에 `설정 수정`, 임시 설정이면 `설정 수정·저장`을 배치한다. `조합 수정`이라는 표현은 생성된 번호 조합을 직접 바꾸는 기능으로 오해될 수 있으므로 사용하지 않는다. |
| RESULT-02 | `다른 설정 선택`을 같은 동작 행의 왼쪽에 배치하되, 저장된 상세 설정이 2개 이상일 때만 활성화한다. |
| RESULT-03 | `설정 수정` 또는 `설정 수정·저장`은 현재 결과와 설정값을 유지한 채 편집 화면으로 이동하므로 경고를 표시하지 않는다. 편집 화면의 상단 뒤로가기는 기존 추천 결과로 돌아간다. |
| RESULT-04 | 별도 제목과 중복되는 첫 문장 없이 `이 화면을 나가면 저장하지 않은 결과는 사라집니다. 저장할 번호가 있다면 결과로 돌아가 저장한 후 이동하십시오.`라고 안내한다. |
| RESULT-05 | 대화상자 버튼은 왼쪽 `결과로 돌아가기`, 오른쪽 `저장하지 않고 이동`으로 한다. |
| RESULT-06 | `결과로 돌아가기`는 결과 화면을 유지한다. `저장하지 않고 이동`은 미저장 결과를 삭제하고 요청한 화면으로 이동한다. 이미 `내 번호` 또는 `저장한 조합`에 저장된 항목은 삭제하지 않는다. |
| RESULT-07 | 미저장 결과도 임시 설정도 없으면 확인 대화상자 없이 이동한다. 임시 설정만 남아 있으면 `현재 설정이 저장되지 않았습니다. 이 화면을 나가면 임시 설정은 사라집니다.`라고 안내한다. 둘 다 남아 있으면 `이 화면을 나가면 저장하지 않은 결과와 임시 설정은 사라집니다. 저장할 항목이 있다면 결과로 돌아가 저장한 후 이동하십시오.`라고 합쳐 안내한다. |
| RESULT-08 | `설정 수정`은 결과 생성에 사용한 상세 설정의 편집 화면으로 이동한다. `다른 설정 선택`은 저장된 설정 목록을 열고, 선택 후 사용자가 `이 설정으로 생성`을 눌러 새 결과를 만든다. |
| RESULT-09 | 추천 결과의 `다시 생성` 또는 상세 설정 편집 화면의 `번호 생성`이 기존 미저장 결과를 교체하는 경우, 생성 전에 동일한 저장 안내를 표시한다. 첫 생성이거나 교체할 기존 결과가 없으면 표시하지 않는다. |
| RESULT-10 | 결과 교체 안내의 제목은 `새 번호를 생성하시겠습니까?`, 내용은 `새 번호를 생성하면 저장하지 않은 현재 결과는 사라집니다. 저장할 번호가 있다면 결과로 돌아가 저장한 후 다시 시도하십시오.`로 한다. 버튼은 `기존 결과로 돌아가기`, `새 번호 생성`으로 한다. |
| RESULT-11 | `기존 결과로 돌아가기`는 생성 요청을 취소하고 기존 결과 화면으로 이동한다. `새 번호 생성`은 기존 미저장 결과를 삭제한 뒤 현재 선택 또는 편집 중인 설정으로 새 결과를 생성한다. 이미 저장한 내 번호와 조합은 유지한다. |
| RESULT-12 | 결과는 생성 당시 설정 스냅샷을 유지한다. 이후 설정만 수정·저장하고 돌아오면 기존 결과의 요약은 생성 당시 값으로 남기고 `생성 후 설정이 변경되었습니다.`라고 표시한다. 임시 설정을 내용 변경 없이 저장한 경우에는 결과의 `임시 설정` 표시를 저장된 이름으로 갱신한다. |
| RESULT-13 | 추천 결과 하단의 왼쪽 버튼은 `다시 생성`, 오른쪽 버튼은 `복권 용지에 저장`으로 표시한다. 기존 `보관함에 저장` 문구는 사용하지 않는다. |
| RESULT-14 | `복권 용지에 저장`을 누르면 생성된 게임 모두를 기본 선택한 화면을 연다. 사용자는 게임별로 선택을 해제할 수 있다. 최소 1개를 선택해야 계속하며, 선택한 게임만 용지에 추가한다. 기존 용지의 빈 칸이 부족하면 게임을 줄이거나 다른 용지·새 용지를 선택하게 한다. |

## 7. 데이터 모델 초안

SQLite를 사용하되 쉼표로 연결한 문자열에 숫자나 ID 목록을 저장하지 않는다.

### `recommendation_presets`

- `id TEXT PRIMARY KEY`: UUID
- `name TEXT NOT NULL UNIQUE`: 사용자 지정 이름 또는 자동 생성된 `설정N`
- `options TEXT NOT NULL`: 스키마 버전이 포함된 상세 설정 JSON
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`

### `favorite_numbers`

- `number INTEGER PRIMARY KEY`: 1~45
- `created_at TEXT NOT NULL`: ISO 8601 UTC 시각

### `number_sets`

- `id TEXT PRIMARY KEY`: UUID
- `source TEXT NOT NULL`: `random`, `configured`, `manual`
- `options_snapshot TEXT`: 생성 당시 설정의 버전이 포함된 JSON
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`

### `number_set_items`

- `set_id TEXT NOT NULL`: `number_sets.id` 참조
- `number INTEGER NOT NULL`: 1~45
- 기본키: `(set_id, number)`
- 앱과 DB 계층에서 한 세트가 정확히 6개인지 검증한다.

### `lottery_papers`

- `id TEXT PRIMARY KEY`: UUID
- `title TEXT NOT NULL`
- `display_style_override TEXT`: 용지별 디자인 ID. 값이 없으면 전역 기본 디자인을 사용한다.
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`

### `lottery_paper_games`

- `id TEXT PRIMARY KEY`: UUID
- `paper_id TEXT NOT NULL`: `lottery_papers.id` 참조
- `source_set_id TEXT`: 선택 사항. 저장한 조합에서 추가한 경우의 `number_sets.id`이며 원본 삭제 후에도 추적 정보로만 사용한다. 임시 조합을 바로 추가하면 `NULL`이다.
- `position INTEGER NOT NULL`: 0~4
- 고유 제약: `(paper_id, position)`; 기본키는 `id`다.

### `lottery_paper_game_items`

- `paper_game_id TEXT NOT NULL`: `lottery_paper_games.id` 참조
- `number INTEGER NOT NULL`: 용지 생성 당시 복사한 1~45 번호
- 기본키: `(paper_game_id, number)`
- 앱과 DB 계층에서 한 게임이 정확히 6개인지 검증한다.

### `display_preferences`

- 단일 행으로 관리한다.
- `mode TEXT NOT NULL`: `global_default`, `per_paper`, `random_each_open`
- `default_style_id TEXT NOT NULL`: 사용자가 마지막으로 저장한 전역 기본 디자인 ID. 최초 값은 앱 기본 디자인이다.
- `last_non_random_mode TEXT NOT NULL`: 마지막으로 사용한 `global_default` 또는 `per_paper` 모드
- 랜덤 모드에서도 `default_style_id`와 각 용지의 `display_style_override`를 삭제하거나 덮어쓰지 않는다.

### `draw_results`

- `round INTEGER PRIMARY KEY`
- `draw_date TEXT NOT NULL`
- 당첨 본번호 6개는 별도 자식 테이블 또는 검증 가능한 고정 열 구조 중 구현 시 결정
- `bonus_number INTEGER NOT NULL`
- `source TEXT NOT NULL`
- `fetched_at TEXT NOT NULL`

외부에서 받은 회차 데이터는 저장 전에 다음 조건을 모두 검증한다.

- 회차는 양의 정수이며 기존 회차와 모순되지 않는다.
- 본번호는 정확히 6개이고 모두 1~45 범위의 서로 다른 숫자다.
- 보너스 번호는 1~45 범위이며 본번호와 겹치지 않는다.
- 추첨일 형식이 유효하고 중간 회차 누락 여부를 확인할 수 있다.
- 검증 실패 데이터는 기존의 마지막 정상 데이터를 덮어쓰지 않는다.

번호 조합을 수정하거나 삭제해도 이미 만든 복권 용지는 생성 당시 번호를 유지한다. `source_set_id`는 출처 추적에만 사용하고, 화면에 표시할 번호는 항상 `lottery_paper_game_items`의 스냅샷에서 읽는다. 임시 조합은 `number_sets`와 `number_set_items`를 만들지 않고 바로 용지 게임 스냅샷으로 저장할 수 있다.

## 8. 추천 엔진 설계 원칙

- UI와 생성 엔진을 분리하여 순수 Dart 코드로 테스트할 수 있게 한다.
- 하나의 거대한 유효성 함수 대신 옵션별 규칙 객체를 조합한다.
- 생성 전에 각 규칙과 규칙 조합의 충돌을 검사한다.
- 고정수 중복, 범위 이탈, 고정수 6개 초과, 고정수와 제외수 중복을 거부한다.
- 후보 번호를 낮은 홀수·낮은 짝수·높은 홀수·높은 짝수 및 외부 데이터 기반 집합으로 분류해 복합 조건의 가능 범위를 계산한다.
- 두 옵션씩은 가능하지만 전체 옵션 조합이 불가능한 경우를 잡기 위해 제한된 백트래킹 또는 동등한 완전성 있는 검증을 수행한다.
- 요구 게임 수만큼 고유한 조합을 만들 수 없는 조건인지 확인한다.
- 최대 시도 횟수에만 의존하지 않고 가능한 경우 후보군을 직접 구성한다.
- 난수 생성기를 주입할 수 있게 하여 재현 가능한 단위 테스트를 작성한다.
- 동일한 유효 조건 아래 특정 조합이 의도치 않게 편향되지 않는지 검증한다.

## 9. 비기능 요구사항

### 접근성

- 텍스트 크기 확대를 지원한다.
- 번호와 상태를 색상만으로 구분하지 않는다.
- 터치 영역은 충분한 크기를 확보한다.
- 스크린 리더가 번호, 저장 상태, 버튼 기능을 읽을 수 있게 한다.

### 개인정보와 저장

- 초기 버전은 회원가입과 개인정보 수집 없이 동작하는 것을 원칙으로 한다.
- 사용자 데이터는 기기에 저장하며 삭제와 초기화 기능을 제공한다.
- 분석·광고 SDK 도입 시 수집 항목과 동의 흐름을 별도로 검토한다.
- `본번호 6개`와 `보너스 포함 7개`의 전체 사용자 사용 비율은 원격 분석 없이는 알 수 없다. 측정 기능을 도입할 경우 명시적 동의, 개인정보처리방침, 데이터 삭제 절차를 갖추고 선택한 범위 값과 기능 버전만 수집한다. 사용자가 선택한 실제 로또 숫자와 저장 조합은 수집하지 않는다.

### 품질

- 추천 규칙과 데이터 변환에는 단위 테스트를 작성한다.
- 데이터베이스 마이그레이션을 버전별로 관리한다.
- 앱이 오프라인에서도 번호 생성, 저장, 용지 열람 기능을 제공한다.
- 통계 데이터 오류가 핵심 저장 데이터에 영향을 주지 않아야 한다.

## 10. 출시 범위

### 1차 출시 후보(MVP)

- 완전 랜덤 및 상세 옵션: 고정수, 제외수, 홀짝, 고저, 총합, 연속수, 직전 회차 번호, 미출현 번호
- 검증된 초기 당첨 데이터와 원격 증분 동기화, 오프라인 대체 동작
- 옵션 자동 저장과 초기화
- 개별 숫자 저장
- 번호 조합 저장 및 직접 입력
- 최대 5게임 복권 용지 생성
- 번호 크게 보기 화면
- 로컬 SQLite 저장
- 옵션별 도움말과 앱 전체 번호 추천 방식 안내
- Android 출시 준비

### 1차 출시 이후

- 홀짝·고저·총합의 과거 추첨 분포 그래프
- 저장 조합 검색, 정렬, 태그
- 데이터 내보내기와 복원

외부 데이터 옵션의 1차 출시 포함은 데이터 출처의 이용 조건, 응답 형식, 안정성, 호출 제한과 장애 대응 방식이 검증되는 것을 전제로 한다. 이 조건을 출시 후보 확정 시점까지 충족하지 못하면 해당 옵션만 기능 플래그로 비활성화하고 나머지 MVP 출시를 막지 않는다.

## 11. 정책 및 표현 검토

- 앱 이름, 설명, 스크린샷에서 당첨 예측이나 확률 상승을 암시하지 않는다.

## 12. 성공 지표 초안

분석 기능을 도입하지 않은 초기 버전에서는 개인정보를 수집하지 않는 수동 품질 지표를 우선한다.

- 번호 생성부터 저장까지 막힘 없이 완료되는가
- 저장한 조합과 저장하지 않은 임시 조합 모두로 복권 용지를 만들 수 있는가
- 실제 사용 환경에서 한 화면을 보며 쉽게 따라 표시할 수 있는가
- 초보 사용자가 도움말만으로 각 옵션의 동작을 설명할 수 있는가
- 충돌하는 옵션에 대해 사용자가 스스로 수정할 수 있는 오류 안내가 제공되는가

추후 분석을 도입한다면 설치 유지율보다도 `번호 생성 → 복권 용지 추가 → 복권 용지 열람` 흐름의 완료율을 핵심 지표 후보로 검토한다.

본번호 6개와 보너스 포함 7개 중 어느 범위를 주로 사용하는지 판단하려면 다음 순서를 따른다.

1. 경쟁 앱과 사용자 리뷰를 조사한다.
2. 소규모 사용성 테스트에서 두 선택지의 이해도를 확인한다.
3. 분석 수집에 동의한 사용자에 한해 범위 선택 이벤트만 익명 집계한다.
4. 충분한 표본과 관찰 기간을 확보한 후 기본값 변경 여부를 결정한다.
5. 기본값이 바뀌어도 기존 사용자의 마지막 설정은 덮어쓰지 않는다.

## 13. 미결정 사항

1. 앱의 최종 사용자명과 스토어 표시 이름
2. 동일 조합 중복 저장을 예외적으로 허용할 사용 사례가 있는지
3. 과거 추첨 데이터의 합법적이고 안정적인 공급 방식
4. 상세 옵션 화면의 초보 모드와 고급 모드 분리 여부
5. 후원 기능의 도입 여부와 정책상 허용되는 구현 방식
6. Android 최소 지원 버전과 iOS 초기 지원 여부
7. 선택지 사용 비율 분석을 1차 출시에 넣을지, 별도의 사용자 조사만 수행할지

## 14. 구현 착수 조건

다음 항목은 외부 데이터 연동과 출시 범위 확정 전에 확인한다. 로컬 모델, 회차 데이터와 분리된 추천 엔진, 화면 구현은 `docs/implementation-design.md`의 순서로 먼저 진행할 수 있다.

- 외부 추첨 데이터의 출처와 배포·저장·갱신 권한
- 추천 결과 및 저장 화면의 최소 와이어프레임
- 옵션 사용 비율 측정의 도입 여부와 개인정보 처리 방식
